## What was the breakthrough that moved the work forward?

The useful breakthrough was separating real-time transport from the meaning
of an action. Dead Air already had SSE, and all 21 existing checks passed.
But two requests based on the same switch position both succeeded, cancelling
one another. A repeated keypad request could reach a stage the player had not
described. Fast delivery alone did not make that fair.

The chosen rule ties each command to the mission and revision the player saw.
The first valid arrival wins; a competing stale command asks for another
read-back without adding a strike. This connects the multiplayer decision to
the existing definition of good: communication is the game. Independent
browser checks then exposed another distinction: holding an old snapshot is
not the same as having a live connection. Screenshot review moved the recovery
warning above the long mobile manual.

## What did this work change about who I want to be as a software developer?

The direction this evidence supports is a developer who makes promises
specific enough to challenge. “SSE already covers real-time” was an assumption;
separate sessions, delayed responses, offline recovery and server restarts made
it testable. The process preserved failing checks and a correction rather than
presenting the first implementation as settled.

This draft cannot establish a personal change of outlook or substitute for
watching classmates play. Those judgements remain mine to review. What the
work provides is a decision I can question, its costs, and repeatable evidence
for the behaviour it claims.
